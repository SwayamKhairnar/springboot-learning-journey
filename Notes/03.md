# 03 - Layered Architecture (Controller &ndash; Service &ndash; Repository)

## Architecture Overview
A well-structured backend separates concerns across three primary architectural tiers:

1. **Controller Layer (`@RestController`)**:
   - Handles incoming HTTP requests (`GET`, `POST`, `PUT`, `DELETE`).
   - Parses path variables, query params, and JSON request bodies.
   - Validates input formats and orchestrates HTTP response status codes.
   - *Rule:* Should never contain business logic or direct database queries.

2. **Service Layer (`@Service`)**:
   - Contains core business logic, domain calculations, workflows, and transactional boundaries (`@Transactional`).
   - Coordinates interactions between multiple repositories and external APIs.

3. **Repository Layer (`@Repository` / Spring Data JPA)**:
   - Responsible strictly for data persistence, database queries, and mapping to relational storage.
   - *Rule:* Contains no business logic.

## Why This Matters
- **Maintainability**: Clear separation means changes in persistence (e.g. switching DBs) do not affect HTTP controllers.
- **Testability**: Services can be unit tested in isolation using mock repositories (e.g., Mockito).
