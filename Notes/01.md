# 01 - Dependency Injection (DI) & Inversion of Control (IoC)

## Core Concepts
- **Inversion of Control (IoC)**: The control of object creation and lifecycle management is shifted from the manual application code (`new` keyword) to the Spring Container (`ApplicationContext`).
- **Dependency Injection (DI)**: The mechanism where Spring injects dependent objects into a class at runtime, promoting loose coupling and easier unit testing.

## Dependency Injection Flavors
1. **Constructor Injection (Recommended)**:
   - Ensures dependencies are immutable (`final`).
   - Prevents `NullPointerException` since objects cannot be instantiated in an incomplete state.
   - Ideal for mandatory dependencies.
2. **Setter Injection**:
   - Useful for optional dependencies or post-construction configuration.
3. **Field Injection (`@Autowired` directly on private fields)**:
   - Works quickly for small experiments, but generally discouraged in production because it hides dependencies and makes testing outside the container harder.

## Key Annotations Used
- `@Component`: Registers a class as a Spring Bean candidate.
- `@Autowired`: Injects a collaborating bean.
- `@Qualifier`: Disambiguates between multiple beans of the same type.
- `@Primary`: Designates the default bean candidate when multiple options exist.
- `@Configuration` & `@Bean`: Explicit programmatic bean definitions.

## Key Takeaways
- IoC removes manual object instantiation and memory management responsibility from the developer.
- Constructor injection makes class dependencies explicit, clean, and testable.
