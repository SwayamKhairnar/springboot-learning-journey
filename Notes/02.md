# 02 - Spring Framework vs. Spring Boot

## Core Differences
Classic Spring Framework required extensive boilerplate configuration before writing any business logic. This included writing verbose XML configuration files (`beans.xml`) or complex `@Configuration` classes, managing servlet dispatchers, and configuring external Tomcat/Jetty application servers manually.

**Spring Boot** was introduced to solve this configuration overhead through **convention-over-configuration** and **opinionated defaults**.

## Comparison Highlights
| Feature | Spring Framework (Classic) | Spring Boot |
|---|---|---|
| **Configuration** | Heavy XML or manual Java configs | Auto-configuration (`@EnableAutoConfiguration`) |
| **Server** | External deployment (WAR file in Tomcat) | Embedded servers (Tomcat/Jetty directly in JAR) |
| **Dependency Management** | Manual version matching across JARs | Starters (`spring-boot-starter-web`, etc.) |
| **Setup Time** | High initial boilerplate | Instant boot with Spring Initializr |

## Key Takeaways
- Spring Boot does **not** replace the Spring Framework; it builds on top of it to dramatically accelerate developer productivity.
- Modern Spring Boot eliminates XML configuration in favor of clean, declarative annotations.
