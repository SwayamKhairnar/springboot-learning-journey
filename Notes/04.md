# 04 - CRUD Operations, Spring Data JPA & H2 Database

## Data Persistence Approaches
During my learning journey, I explored multiple ways Java applications interact with databases:

1. **In-Memory Collections / Stream API**: Great for initial prototype understanding, but lacks durability across restarts.
2. **Raw JDBC**: Full control over low-level SQL queries, but requires substantial repetitive boilerplate (Connection, Statement, ResultSet handling).
3. **ORM (Hibernate)**: Automatically maps Java objects to relational tables, managing schema generation and session caching.
4. **Spring Data JPA**: The highest-level abstraction &mdash; creates repository implementations automatically at runtime simply by defining an interface extending `JpaRepository<T, ID>`.

## Annotations Explored
- `@Entity`: Marks a Java class as a JPA entity mapped to a database table.
- `@Id`: Defines the primary key.
- `@GeneratedValue(strategy = GenerationType.IDENTITY)`: Auto-increments primary keys.
- `@Lob`: Marks large binary objects (BLOBs) for image storage.
- `@Query`: Enables custom JPQL (Java Persistence Query Language) queries.

## H2 In-Memory Database
- Embedded, zero-configuration database running inside the JVM process.
- Ideal for fast automated testing and local development cycles.
- Features a built-in web console at `/h2-console` for real-time table and query inspection.

## Key Takeaways
- Spring Data JPA eliminates up to 90% of data-access boilerplate.
- Keeping entities clean (domain models only, not Spring beans) prevents unexpected lifecycle issues.
